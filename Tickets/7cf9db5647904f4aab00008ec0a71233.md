# tests-plain-enum-accessors

Repair hand-written xUnit tests that reference union-projection accessors on enums that step three (ca6aafa) now projects as plain C# enums.

First break, found by building Tests.csproj (the first build of these files in this configuration):
  Test.Pattern.Services.Async.Result.cs(27,33): error CS1061:
  'Error' does not contain a definition for 'IsFail'

Error is a unit-only enum (crates/reference_project/src/patterns/result.rs), so it is now `enum Error : byte` and has no Is* accessors. Line 27 sits in `catch (EnumException<Error> e)`, so e.Value is an Error. Replace `Assert.True(e.Value.IsFail)` with `Assert.Equal(Error.Fail, e.Value)` - expected-first, which is also what the xUnit2000 analyzer wants and what Test.Pattern.Strings.cs already does.

Scope check already done: 15 `.Is[A-Z]` hits across the 45 files in Tests/. Of those, .IsWindows/.IsDynamicCodeSupported/.IsNaN are BCL, and .IsOk/.IsErr/.IsPanic/.IsNull are on ResultVoidError, ResultVoidVoid and result-interface types which carry payloads and therefore stay union-projected with their accessors intact. Only .IsFail on Error is broken.

The compiler stops at the first error, so rebuild after this fix and expect further unrelated breaks; these files have never been compiled in this configuration.
